In this chapter you'll render rich text content, including its links and images.

== Intro

Enonic has a {cms-docs}/{cms-docs-version}/schemas/form-items/htmlarea[rich text form item] which, unlike basic text fields, may contain more complex concepts such as tables, images, links and custom components. Each of these typically needs to be processed during rendering to provide a contextually correct URL, ideal image sizes, etc.

== Sample content

The sample data set contains everything you need to get going.

== Task: Render rich text

. *Update the Person query* - To properly render rich text, you need access to additional metadata (such as links and images) within it.
+
Next.XP provides a `richTextQuery` helper function that generates the query for you. This way you don't have to repeat the query for every rich text field.
+
Add a new query file to your project with the following content:

+
IMPORTANT: Since `${richTextQuery('bio')}` depends on the registered macros, the `getPersonWithBio` query is a function!
This guarantees that it is executed when querying for data, and all the macros are already registered.
+
NOTE: `RichTextView` rewrites media `src`, `srcset` and `href` attributes to absolute XP media URLs and content links to locale-prefixed Next.js routes, so no URL handling is needed in your views.
+
The processed HTML from Guillotine {guillotine-version} contains placeholders. The adapter matches `data-link-ref` and `data-image-ref` with the structured links and images, preserving page-link query strings and fragments.
Apps providing macros and image styles must be configured on the selected site or project.
+
For further insight, visit the {dev101-tutorial}/{dev101-tutorial-version}/rich-text[rich text chapter] in the Developer 101 tutorial, or have a look at the {reactspa-tutorial}[React SPA tutorial], which covers Enonic's standard React components.

. *Update the mapping* - Update the mappings to use the new query and view.
+
Replace the `getPerson` query with `getPersonWithBio` and the `Person` view with `PersonWithBio`. It should look something like this:
+
.src/components/_mappings.ts
[source,typescript]
----
import getPersonWithBio from './queries/getPersonWithBio';
import PersonWithBio from './views/PersonWithBio';

ComponentRegistry.addContentType(`${APP_NAME}:person`, {
    query: getPersonWithBio,
    view: PersonWithBio
});
