In this chapter you will learn about the static site generation capabilities of Next.js, and how Enonic triggers regeneration of pages when content is published.

== Introduction

Your Next.js front-end uses Static Site Generation (SSG) when possible. This gives you fast pages, but adds a build step.

For more information visit the https://nextjs.org/docs/app/building-your-application/rendering[Next.js rendering documentation].

== Task: Activate prod mode

So far, you have been running Next.js in dev mode.

By starting Next.js in `prod` mode, the application is automatically optimized, and in this case, pages get pre-rendered statically before the server starts.

. *Stop the dev server* - Stop your existing Next.js dev instance before you continue.

. *Start Next.js in prod mode*:
+
[source,shell]
----
npm run prod
----
+
This takes longer than starting dev mode, since the application is built first.

. *Verify the result* - Point your *incognito window* to http://localhost:3000[http://localhost:3000]. You should see the published items, like in dev mode.
Only this time, they load much faster.

NOTE: Since prod mode runs on the default port 3000 (same as dev mode), Content Studio preview continues to work without any configuration changes.
The draft cookie issued by the dev server belongs to another build, so the proxy sends the first preview request through `/api/preview` again and draft mode is re-enabled for the prod build.

== Task: Test page invalidation

With all pages now being cached as files, Next.js must be instructed to regenerate the pages when a change is published.

. *Check the site* - Verify that the `Next.XP` app is added to your site, and that the site is published. You added the app in the <<preview#,Preview>> chapter, and published the site in the <<pages#,Pages>> chapter.
This ensures that the revalidation hook is triggered when you publish content.

. *Edit your front page, and publish the changes* - This triggers a revalidation hook, which is built into the Next.XP app.

. *Verify the update* - The page at http://localhost:3000[http://localhost:3000] is updated more or less instantly.

=== What happened?

In addition to handling previews, the Next.XP app automatically triggers revalidation of all pages when it detects the publishing event in the site it is added to.
The `/api/revalidate` route resolves the locale from the publishing project, so a specific path is revalidated as its locale-prefixed page; without a path everything is revalidated.

NOTE: The Next.js log also shows that the revalidation was triggered.
